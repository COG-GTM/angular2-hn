<p align="center">
  A progressive Hacker News client built with React, TypeScript and Vite
</p>

---

:zap: **Fast:** App shell precached by a Workbox service worker, with Hacker News API responses cached at runtime.

:iphone: **Responsive:** Completely responsive UI that can be installed to your mobile home screen to provide a native feel.

:rocket: **Progressive:** Installable web app manifest, offline support and instant repeat loads.

## Stack

* [React 18](https://react.dev) with function components and hooks
* [TypeScript](https://www.typescriptlang.org) in strict mode
* [Vite 5](https://vitejs.dev) for dev server and production builds
* [React Router 6](https://reactrouter.com) for routing
* [Sass](https://sass-lang.com) for the theme engine
* [vite-plugin-pwa](https://vite-pwa-org.netlify.app) (Workbox) for the service worker and manifest

Data comes from [node-hnapi](https://github.com/cheeaun/node-hnapi) (`https://node-hnapi.herokuapp.com`).

## Getting started

```bash
npm install     # install dependencies
npm start       # dev server on http://localhost:4200
npm run build   # type-check and build to dist/
npm run preview # serve the production build (service worker included)
npm run lint    # eslint
npm test        # vitest
```

## Project layout

```
index.html              app shell entrypoint
public/                 static assets copied verbatim (icons, favicon, images)
src/main.tsx            React entrypoint
src/App.tsx             theme wrapper, header/footer, router outlet
src/routes.tsx          route definitions
src/pages/              feed, item and user pages
src/components/         header, footer, settings panel, loader, error message
src/services/           Hacker News API client
src/hooks/              shared hooks (useAsync)
src/context/            settings context (theme and display preferences)
src/models/             shared TypeScript types
src/styles/             theme variables, themes and media query helpers
vite.config.ts          Vite and PWA (Workbox) configuration
```

## Themes

Built in theme engine, driven by class names on the app root and the Sass files in `src/styles/`.

Current themes:
* Default
* Night
* Black (AMOLED)

The theme is selected from the settings panel and persisted in local storage.

## Offline support

The service worker is generated by `vite-plugin-pwa` at build time and is registered in production builds only,
so it never gets in the way during development:

* the app shell (`index.html`, hashed JS/CSS, icons and images) is precached,
* requests to `https://node-hnapi.herokuapp.com` use a `NetworkFirst` strategy, so feeds and items already
  visited keep rendering with no network.

To try it locally:

```bash
npm run build && npm run preview
```

Then open the app, check `Application -> Service Workers` in devtools, tick `Offline` and reload.

## Manifest

The web app manifest is generated by `vite-plugin-pwa` from the `manifest` block in `vite.config.ts` and is
emitted as `manifest.webmanifest`; `index.html` links it exactly once (the link tag is injected at build time).

## Deploy

Hosted on Firebase Hosting. `firebase.json` serves `dist/`, rewrites all routes to `/index.html`, caches hashed
assets for a year and keeps `index.html`, the service worker and the manifest uncached.

```bash
npm ci && npm run build
firebase deploy --token $FIREBASE_TOKEN
```

CI runs the same steps on `master` (see `.travis.yml`).
